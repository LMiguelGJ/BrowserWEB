Tercer feedback, verbatim: «hay problemas al parareser solo puedo conseguir una ip gratis dos y ademas me sale el anti bot en la pagina cuando con la ip de dataimpulse esto no me pasa», con el log del contenedor. Tres hallazgos: (1) **el app envenenaba el pool**: reportaba al pool como avería cualquier fallo de medición, y el pool da de baja un proxy tras tres reportes, así que un proxy lento pero funcional (latencia típica 2,6 s) acababa retirado del inventario. Ahora solo se acusa al proxy cuando el navegador dice que el proxy rechazó la conexión (`NS_ERROR_PROXY_*`, `ERR_PROXY_*`, `ECONNREFUSED`); un timeout o un servicio de IP caído no lo acusan. Además la medición usa todo el presupuesto restante (12 s) en vez de recortar cada servicio a 5 s, para que un proxy lento tenga su oportunidad, y el motivo del fallo viaja en el mensaje para poder distinguir. (2) Supervisor avisaba `CRIT Server 'unix_http_server' running without any HTTP authentication checking`: se retiraron las secciones `[unix_http_server]` y `[supervisorctl]`, porque el control de los dos procesos se hace con señales y logs y no hace falta un socket de administración. No se cambia el código por eso, pero queda documentado para que la decisión sea del operador.
